# 设计：NPM 全局发行与用户态运行

## 责任边界

| 层 | 责任 |
| --- | --- |
| 发布构建 | 编译后端、构建前端、复制必要运行资源并生成候选压缩包 |
| NPM 包 | 提供 `ozw` 命令和不可变的程序资产，不保存用户数据 |
| CLI 启动层 | 解析命令、初始化用户目录、装载配置并启动已编译服务 |
| 用户目录 | 保存 `.env`、数据库、JWT 内部密钥、日志和服务状态 |
| 运行时诊断 | 检测外部编程代理是否存在、可连接或已认证，只报告结果 |
| 系统服务适配 | 可选地注册 ozw 自身服务，复用同一 CLI 和用户目录 |
| 发布流水线 | 验证、打包、跨平台安装、发布和发布后冒烟检查 |

## 发行与运行数据流

```text
源码与锁文件
    ↓ 发布前构建
编译后端 + 前端静态资源 + 必要运行资源
    ↓ npm pack 内容审计
不可变 NPM 压缩包
    ↓ npm install -g
全局程序目录
    ↓ ozw
~/.ozw/.env + ozw.db + .jwt-secret + 运行状态
    ↓
本地 WebUI、API 与 WebSocket
```

全局程序目录可以随升级或卸载被替换；`~/.ozw` 是稳定用户状态边界。程序不得把可变数据写回 `node_modules` 或压缩包解包目录。

## 关键决策

### 1. NPM 是主发行渠道，发布的是成品

保留现有 `name`、`version`、`main`、`bin` 和 `prepublishOnly` 基础，但调整职责：

- 发布流水线先完成后端编译和前端构建；
- `bin.ozw` 指向可由 Node.js 直接执行的编译产物；
- 用户运行 `ozw` 或安装包生命周期时不得调用 pnpm、tsx、tsc、Vite；
- `start` 若保留为开发脚本，文档必须明确它不是全局用户入口；
- 安装脚本只允许处理确有必要的原生模块安装，不承担源码修补或产品构建。

当前 `postinstall` 通过 `tsx` 执行源码脚本，是必须消除的发行缺口。若 `node-pty` 或其他原生依赖需要兼容处理，应改用预编译 JavaScript或由依赖自身标准安装流程完成，并在离线包内容和跨平台测试中证明必要性。

### 2. 发布清单使用允许列表

当前 `files` 包含 `backend/`、`shared/` 和整个 `scripts/`，这会把源码及开发脚本带入成品。目标清单只允许：

- 编译后的服务端目录；
- 构建后的前端静态目录和 `public` 中运行时仍需的资产；
- 数据库初始化与迁移资源；
- 必要的已编译安装或服务适配脚本；
- `package.json`、许可证和最小使用说明。

验收必须检查 `npm pack --json` 或等价清单及解包结果，既验证“必需文件都在”，也验证“源码、测试、构建配置、缓存、开发脚本不在”。`.npmignore` 不得与 `files` 形成互相矛盾的双重规则；优先以 `files` 允许列表作为可审阅事实。

### 3. 用户目录与配置优先级统一

默认用户目录为 `path.join(os.homedir(), '.ozw')`，默认文件包括：

| 路径 | 用途 | 权限原则 |
| --- | --- | --- |
| `~/.ozw/.env` | 用户可配置项和访问令牌 | 仅当前用户读写 |
| `~/.ozw/ozw.db` | 单用户数据库 | 仅当前用户读写 |
| `~/.ozw/.jwt-secret` | 内部会话签名密钥 | 仅当前用户读写，不写入 `.env` |
| `~/.ozw/logs/` | 可选运行日志 | 不包含明文令牌和内部密钥 |
| `~/.ozw/run/` | 可选服务状态 | 可安全重建，不作为业务数据 |

配置优先级保持简单且一致：显式进程环境变量高于 `~/.ozw/.env`，后者高于程序默认值。CLI、服务端、`status`、`doctor` 和系统服务必须调用同一解析器，不得再读取安装包根目录 `.env`。

测试可以通过显式环境变量把用户目录重定向到临时位置，但生产默认路径保持 `~/.ozw`。

### 4. 首次运行是幂等初始化，不是账号注册

首次执行任何需要运行配置的命令时：

1. 以仅当前用户可访问的权限创建 `~/.ozw`。
2. `.env` 不存在时创建它；存在时只补充明确允许自动补充的缺失项，不改写用户已有值。
3. 缺少 `OZW_ACCESS_TOKEN` 时使用密码学安全随机源生成恰好 32 个字符的令牌，并安全写入 `.env`。
4. JWT 签名密钥仍由运行时自动生成并写入 `.jwt-secret`，不展示、不要求用户记忆。
5. 初始化数据库和迁移后启动服务。
6. 首次生成访问令牌时在当前终端展示一次，并始终显示登录地址；日志不得重复泄漏令牌。

并发启动必须使用原子创建或等价锁，确保两个进程不会生成两套令牌、内部密钥或互相截断配置。已有无效令牌应给出可操作错误，不得静默换新导致其他客户端失效。

### 5. 外部编程代理只诊断、不管理

ozw 可以检测以下能力并在 WebUI、`status` 或未来 `doctor` 中报告：

- Claude Code、Codex、Pi 命令是否在 `PATH`；
- 所需版本或协议是否兼容；
- 当前连接或认证是否可用；
- 独立 Codex Server 的连接端点是否可达。

ozw 不安装、登录、启动、停止、重启、升级这些程序，不修改其配置，也不接管 Codex Server 守护进程。依赖缺失时，除确属某项功能的硬依赖外，ozw 主服务仍应启动，并把影响限定为对应功能不可用。

### 6. 前台运行优先，系统服务后置

首期唯一必需入口是前台 `ozw`：日志直接输出到终端，接收终止信号后有序关闭。可选系统服务在后续阶段实现，要求：

- 只管理 ozw 自身，不管理外部编程代理；
- Linux、macOS、Windows 分别使用平台标准服务机制；
- 服务命令调用同一个已编译启动入口；
- 继承用户目录、端口和配置规则，不另建第二份配置；
- 安装、状态、卸载操作可重复执行，并清楚报告实际服务文件位置。

系统服务不是首个 NPM 公开版本的阻断项；前台安装闭环通过后才能进入该阶段。

### 7. 升级与卸载遵循 NPM 语义

- 升级使用 `npm update -g ozw` 或安装指定版本，程序启动时执行向前兼容的数据库迁移。
- 发布说明必须标明 Node.js 支持范围、数据迁移和可能的破坏性变化。
- 升级失败不得破坏既有数据库；需要不可逆迁移时先备份或提供明确恢复路径。
- `npm uninstall -g ozw` 只移除程序，不删除 `~/.ozw`。
- 若未来提供 `ozw data remove`，必须显式确认准确路径，且不能作为 NPM 卸载脚本的隐式动作。
- 系统服务若已安装，卸载 NPM 包前应先给出移除服务的明确步骤；流水线需要验证不会遗留指向不存在程序的服务定义。

### 8. `better-sqlite3` 决定支持矩阵

`better-sqlite3` 是原生模块，NPM 包可安装不等于所有平台都能运行。发布门禁至少覆盖项目声明支持的 Node.js 版本及：

- Linux x64、Linux arm64；
- macOS x64、macOS arm64；
- Windows x64；
- 其他平台只有通过真实矩阵后才能加入支持列表。

每个矩阵项从候选压缩包执行真实全局安装，随后加载原生模块、创建数据库、运行迁移并完成读写。优先使用上游预编译二进制；若某矩阵会回退本机编译，文档必须明确编译工具要求，或把该矩阵标为不支持。不能让普通用户在不知情的情况下承担 Python、C++ 工具链或系统 SQLite 依赖。

当前同时依赖 `better-sqlite3`、`sqlite3` 和封装库，执行阶段应先确认生产调用面，只保留真实运行需要的数据库依赖，避免扩大原生安装风险。

### 9. 低端设备使用可复现的分段性能合同

Node.js 的单事件循环不等于所有工作只能串行；真正需要防止的是请求路径中的同步磁盘 I/O、全量历史遍历、同步外部命令和无界计算。只在量化证据表明某项 CPU 工作会持续占用事件循环时，才引入 Worker 或独立进程，不为“多线程化”本身扩大架构。

发布门禁使用仓库固定的 Linux 性能剖面，而不使用开发者电脑或某个 NAS 型号作为基准：

| 维度 | 可复现剖面 |
| --- | --- |
| 计算资源 | 1 个虚拟中央处理器配额、512 MiB 内存，最多 4 个并发首页请求 |
| 应用状态与 Provider 夹具磁盘 | 本地块存储，固定注入 20 ms I/O 延迟和 10 MiB/s 吞吐上限 |
| 数据规模 | 100 个项目摘要、5000 条已索引会话、10000 个带固定小正文的 Provider 历史文件 |
| 外部依赖 | Claude Code、Codex、Pi 探测各延迟 2 秒或不可用 |
| 冷路径 | 每轮新进程、清空应用级缓存；已有完成迁移的用户数据库 |
| 热路径 | 同一进程先完成 1 次预热，随后采样 20 次 |

注入延迟要由性能工具统一控制，避免操作系统页缓存或 CI 机器型号改变测试含义。每个候选包至少采样 20 轮，保存中位数、95 分位和最大值；95 分位是发布门禁，最大值用于识别异常尖峰。

| 分段 | 起止点 | 冷路径 95 分位 | 热路径 95 分位 |
| --- | --- | ---: | ---: |
| 首次初始化到健康 | 进程创建到首个成功 `/health` 响应 | 5 秒 | 不适用 |
| 已初始化进程到健康 | 进程创建到首个成功 `/health` 响应 | 3 秒 | 不适用 |
| 登录页可用 | 未认证请求 `/`，直到 HTML 首字节与 `/api/auth/status` 成功完成 | 500 ms | 250 ms |
| 认证首页可用 | 带会话请求 `/`，直到 `/api/auth/user` 与首个 `/api/projects` 成功完成 | 1.5 秒 | 500 ms |
| 项目列表首字节 | 认证请求 `/api/projects` 到首字节 | 800 ms | 250 ms |
| 事件循环停顿 | 首页请求与后台索引并行期 95 分位 / 单次上限 | 100 ms / 250 ms | 100 ms / 250 ms |

除时间预算外，还必须记录请求前的文件系统操作数和读取字节数。进程健康前不得遍历 Provider 历史或等待外部探测；`/api/projects` 不得递归遍历 Provider 目录或读取 transcript 正文。将 transcript 正文总体积扩大 10 倍时，项目列表路径的文件操作数必须不变，95 分位不得增加超过 10%。

#### NAS 与 SQLite 存储边界

ozw 进程可以运行在 NAS 或低配云服务器，项目工作区和 Provider 历史也可以位于网络共享；这些慢目录不得进入健康、登录或项目摘要的同步路径。

`~/.ozw/ozw.db` 及 SQLite 旁路文件应放在对 ozw 进程而言的本地文件系统。NAS 内部直接挂载的本地磁盘卷符合这一边界；从另一台机器挂载的 NFS、SMB/CIFS、WebDAV 或其他网络文件系统不建议保存 SQLite，不纳入一致性和性能保证。若用户主目录是网络挂载，文档必须要求用 `DATABASE_PATH` 指向本地卷；配置、内部密钥、数据库及其 WAL/SHM 的实际路径必须出现在验收证据中，但不记录密钥明文。

这些数值是可控剖面下的发布回归门禁，不是对所有硬件、磁盘故障或网络共享的通用绝对承诺。

### 10. 发布流水线发布同一个已验收产物

流水线分为：

```text
质量门
  ↓
构建一次
  ↓
npm pack + 内容/体积审计
  ↓
跨平台安装与运行矩阵
  ↓
人工批准或受保护发布条件
  ↓
npm publish
  ↓
从公开注册表重新安装并冒烟
```

现有 `release.sh` 只更新版本、生成提交和标签，应保留为版本准备工具或被流水线取代，但不能继续被描述为已发布。注册表发布必须使用受保护的自动化身份，拒绝脏工作树、版本与标签不一致、未通过矩阵或压缩包内容变化。正式发布必须发布矩阵验收过的同一压缩包，不能在最后一步重新构建另一份产物。

首个公开版本还需确认 `ozw` 包名的注册表所有权；若名称不可用，只调整发行包名，命令名 `ozw` 可以保持不变。

## 分阶段实施

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| 1. 成品边界 | 可直接执行的编译产物、最小 `files` 清单、无 pnpm/tsx 运行依赖 | 本地压缩包可在隔离前缀启动 |
| 2. 首次初始化 | 统一 `~/.ozw`、自动令牌、内部密钥和数据库初始化 | 并发与重复启动不覆盖状态 |
| 3. 安装验收 | 干净环境、升级、卸载、产物内容与体积合同 | Linux 主支持矩阵稳定通过 |
| 4. 低端性能 | 单核慢磁盘分段时延、I/O 计数和事件循环证据 | 冷、热路径均通过发布预算 |
| 5. 跨平台 | `better-sqlite3` 真实安装、迁移和读写矩阵 | 所有对外声明平台通过 |
| 6. 注册表发布 | 受保护发布、公开安装冒烟、发布文档 | `npm install -g ozw && ozw` 可复现 |
| 7. 可选系统服务 | 各平台 ozw 自身服务适配 | 不影响前台入口，不管理外部代理 |

阶段 1 至 6 构成首次正式 NPM 发行；阶段 7 可以独立延期。

## 风险与取舍

| 风险 | 控制 |
| --- | --- |
| 原生模块缺少某平台预编译产物 | 真实矩阵决定支持列表，不以“理论可编译”代替验收 |
| 全局安装目录只读或升级时被替换 | 所有可变状态固定写入 `~/.ozw` |
| 首次并发启动产生不同密钥 | 原子创建、权限检查和幂等初始化 |
| 发布清单漏资产导致启动后 404 | 从真实压缩包启动并访问 WebUI、API、WebSocket |
| 发布清单过大泄漏源码或测试 | 允许列表、内容快照和体积预算 |
| 安装脚本成为供应链风险 | 最小化生命周期脚本，流水线审计其内容与网络行为 |
| 升级触发不可逆数据库问题 | 迁移测试、备份策略和旧数据夹具 |
| 慢磁盘让同步 I/O 放大为全局卡顿 | 单核延迟注入、事件循环停顿门禁和请求路径 I/O 计数 |
| SQLite 放在网络文件系统 | 文档明确排除，验收保存实际数据路径与存储类型 |
| 系统服务扩大首发范围 | 作为独立后置阶段，不阻断前台发行 |

## 范围外事项

- 图形桌面安装器、Electron 外壳与内置浏览器。
- 把 Node.js 或 NPM 打入单文件可执行程序。
- Docker、NAS 应用商店和远程托管部署。
- OZW 自更新器；版本更新继续交给 NPM。
- 外部编程代理与 Codex Server 的安装、认证、进程管理和升级。
- 多用户账号、管理员初始化和云端密钥同步。
