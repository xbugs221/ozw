# 规格：NPM 全局应用发行

## 验收矩阵

| 需求 / 场景 | 计划测试 | 必要证据 |
| --- | --- | --- |
| 发布包是预编译成品 / 全局命令不需要开发工具 | `npm-package-runtime` | 压缩包清单、隔离启动日志 |
| 首次运行初始化用户目录 / 自动生成访问令牌和内部密钥 | `first-run-bootstrap` | 用户目录快照、权限与重复运行结果 |
| 配置和数据独立于安装目录 / 升级与卸载保留数据 | `upgrade-uninstall-data` | 版本前后数据库与配置校验 |
| 依赖只检测不管理 / 缺失代理不阻断主服务 | `provider-diagnostics-boundary` | 进程与文件变更记录、诊断输出 |
| 单核慢磁盘仍能快速进入首页 / 请求路径不扫描历史 | `low-end-runtime-budget` | 分段冷、热延迟，I/O 计数和事件循环停顿 |
| 原生数据库跨平台可运行 / 每个声明平台真实读写 | `native-database-matrix` | 平台矩阵与 SQLite 读写日志 |
| 发布流水线只发布验收产物 / 公开注册表可重装 | `release-artifact-identity` | 压缩包摘要、公开安装冒烟 |
| 可选系统服务复用主入口 / 只管理 ozw 自身 | `optional-service-boundary` | 服务定义与生命周期日志 |

## 需求：发布包必须是预编译的生产成品

### 场景：全局安装后直接运行 `ozw`

- **给定** 干净环境只有受支持的 Node.js 与 NPM
- **当** 用户从候选压缩包或公开注册表执行 `npm install -g ozw`，随后运行 `ozw`
- **则** WebUI、API 和 WebSocket 必须由同一个已编译服务正常提供
- **且** 安装和启动不得调用 pnpm、tsx、tsc、Vite 或读取源码树
- **且** `bin.ozw` 必须指向真实存在且可由 Node.js 直接执行的产物

### 场景：压缩包只包含生产运行资产

- **给定** 发布流水线已经完成构建
- **当** 审阅者检查 `npm pack` 的文件清单和解包内容
- **则** 必须包含编译后端、前端静态资源、运行时 public 资产、数据库初始化或迁移资源、命令入口、许可证和最小文档
- **且** 不得包含测试、TypeScript 源码、构建配置、缓存、开发依赖脚本或完整通用 `scripts/` 目录
- **且** 对压缩包执行真实启动时不得出现缺失静态资源或数据库资源

### 场景：安装生命周期不承担产品构建

- **给定** 当前 `postinstall` 仍通过 `tsx` 运行源码脚本
- **当** 执行阶段完成发行改造
- **则** `postinstall` 必须被删除，或改为 Node.js 可直接执行且确有必要的最小生产脚本
- **且** 生命周期脚本不得编译 TypeScript、构建前端、下载浏览器或修改全局包中的产品源码

## 需求：首次运行必须安全初始化单用户环境

### 场景：首次运行创建 `~/.ozw` 和访问令牌

- **给定** 用户主目录中不存在 `.ozw`
- **当** 用户第一次运行 `ozw`
- **则** 程序必须创建 `~/.ozw/.env` 和默认数据库位置
- **且** `.env` 必须包含由密码学安全随机源生成、恰好 32 个字符的 `OZW_ACCESS_TOKEN`
- **且** 目录和敏感文件权限必须限制为当前用户
- **且** 终端必须清楚显示登录地址，并仅在新生成令牌时展示令牌

### 场景：JWT 密钥自动生成且不进入用户配置

- **给定** `~/.ozw/.jwt-secret` 不存在
- **当** 服务初始化认证运行时
- **则** 程序必须自动生成足够强度的 JWT 签名密钥并安全保存
- **且** `.env`、帮助文本和首次登录流程不得要求用户设置或记忆该密钥
- **且** 日志不得输出该密钥

### 场景：重复或并发启动不覆盖已有状态

- **给定** `.env`、访问令牌、数据库或 JWT 密钥已经存在
- **当** 用户再次启动，或两个 ozw 进程同时尝试初始化
- **则** 既有值和数据库内容不得被截断或替换
- **且** 两个进程必须观察到同一套持久化秘密
- **且** 无效的已有访问令牌必须产生可操作错误，不得被静默换新

## 需求：配置与数据必须独立于全局安装目录

### 场景：所有运行入口共享用户目录

- **给定** ozw 安装在全局 NPM 前缀且安装目录不可写
- **当** 用户运行 `ozw`、`ozw status`、运行时诊断或可选系统服务
- **则** 所有入口必须读取同一个 `~/.ozw/.env`
- **且** 数据库、内部密钥、日志和运行状态只能写入用户目录或显式覆盖路径
- **且** CLI 不得把安装包根目录 `.env` 报告为当前配置来源

### 场景：显式环境变量优先于用户配置

- **给定** `~/.ozw/.env` 已设置端口或数据路径
- **且** 当前进程提供相同配置的显式环境变量
- **当** ozw 启动并显示状态
- **则** 显式环境变量必须生效
- **且** `status` 必须报告实际生效路径和值来源，不得显示另一套推测结果

## 需求：外部编程代理必须只检测、不管理

### 场景：依赖诊断不改变外部程序状态

- **给定** 环境可能安装 Claude Code、Codex、Pi 或独立 Codex Server
- **当** ozw 启动或运行诊断
- **则** ozw 可以检查命令、版本、协议、认证或连接状态
- **但** 不得安装、登录、启动、停止、重启、升级或修改这些程序的配置
- **且** 不得创建或删除其系统服务

### 场景：可选代理缺失时主服务仍可启动

- **给定** 一个或多个外部编程代理未安装或未认证
- **当** 用户运行 `ozw`
- **则** ozw 必须启动所有不依赖该代理的功能
- **且** 诊断必须指出缺失依赖及受影响功能
- **且** 不得在启动路径自动执行 NPM 安装或其他外部修复

## 需求：升级和卸载必须保护用户数据

### 场景：标准 NPM 升级保留配置和数据库

- **给定** 用户已经使用旧版 ozw 并拥有 `~/.ozw` 数据
- **当** 用户执行 `npm update -g ozw` 并启动新版
- **则** 新程序必须继续读取同一访问令牌、JWT 密钥和数据库
- **且** 必要迁移必须成功完成并保持已有业务数据可读
- **且** 程序资产升级不得依赖旧版全局安装目录中的可变文件

### 场景：卸载程序默认不删除用户数据

- **给定** 用户已安装并使用 ozw
- **当** 用户执行 `npm uninstall -g ozw`
- **则** 全局程序必须被移除
- **且** `~/.ozw` 必须保留
- **且** NPM 卸载生命周期不得隐式删除数据库、配置、令牌或日志

## 需求：低端单核与慢磁盘不得阻塞启动和首页

### 场景：固定低端剖面分段验收冷、热路径

- **给定** 候选压缩包运行在 1 个虚拟中央处理器配额、512 MiB 内存的固定 Linux 剖面
- **且** 本地应用状态与 Provider 夹具磁盘注入 20 ms I/O 延迟和 10 MiB/s 吞吐上限
- **且** 夹具包含 100 个项目摘要、5000 条已索引会话和 10000 个带固定小正文的 Provider 历史文件
- **且** 外部代理探测各延迟 2 秒或不可用
- **当** 新进程冷启动、首次初始化和同进程预热后路径分别采样至少 20 次
- **则** 每一分段必须记录中位数、95 分位、最大值、文件系统操作数和读取字节数
- **且** 首次初始化到健康的 95 分位不得超过 5 秒，已初始化进程到健康不得超过 3 秒
- **且** 未认证请求 `/` 直到 HTML 首字节与 `/api/auth/status` 完成的冷、热 95 分位不得分别超过 500 ms 和 250 ms
- **且** 认证首页完成 `/api/auth/user` 与首个 `/api/projects` 的冷、热 95 分位不得分别超过 1.5 秒和 500 ms
- **且** `/api/projects` 首字节的冷、热 95 分位不得分别超过 800 ms 和 250 ms

### 场景：慢后台工作不占用事件循环和首页关键路径

- **给定** Provider 增量索引与 4 个并发首页请求同时运行
- **当** 性能工具持续采样事件循环停顿
- **则** 停顿的 95 分位不得超过 100 ms，任一单次停顿不得超过 250 ms
- **且** 首个成功 `/health` 响应前不得递归遍历 Provider 历史或等待外部代理探测完成
- **且** Provider watcher 必须在 HTTP 监听后后台启动，不得等待 watcher `ready` 才开放 `/health`
- **且** `/api/projects` 不得递归遍历 Provider 目录或读取 transcript 正文
- **且** 把 transcript 正文总体积扩大 10 倍后，该接口的文件操作数必须不变，95 分位增幅不得超过 10%
- **且** 单个 Provider 的慢盘、超时或失败只能延后其增量结果，不得阻止已有项目摘要返回

### 场景：NAS 部署保持本地 SQLite 边界

- **给定** ozw 进程运行在 NAS 或低配云服务器
- **则** 项目工作区和 Provider 历史可以位于网络共享，但其遍历不得进入健康、登录和项目摘要同步路径
- **且** SQLite 数据库及 WAL/SHM 应位于对 ozw 进程而言的本地文件系统
- **且** NAS 内部直接挂载的本地磁盘卷视为本地存储
- **且** NFS、SMB/CIFS、WebDAV 等网络文件系统上的 SQLite 不纳入性能或一致性保证
- **且** 用户主目录为网络挂载时，文档必须要求用 `DATABASE_PATH` 指向本地卷
- **且** 验收证据必须记录程序、配置、内部密钥和数据库的实际路径与存储类型，但不得记录秘密明文
- **且** 性能预算必须明确是可控剖面下的发布门禁，不得表述为对任意硬件的绝对承诺

## 需求：每个声明支持的平台必须通过原生数据库验收

### 场景：候选包在平台矩阵真实安装

- **给定** 同一个候选 NPM 压缩包
- **当** 流水线分别在声明支持的操作系统、架构和 Node.js 版本上全局安装
- **则** `better-sqlite3` 必须成功加载
- **且** ozw 必须创建数据库、运行迁移并完成真实读写
- **且** 没有通过的组合不得列入 README 或包元数据的支持范围

### 场景：普通安装不隐含完整本机编译工具链

- **给定** 某平台没有适配的原生预编译模块
- **当** NPM 安装尝试回退本机编译
- **则** 该平台必须被明确标记为需要构建工具或暂不支持
- **且** 发布文档不得把它描述为普通下载即用
- **且** 流水线不得用预装但未声明的编译工具掩盖用户环境失败

## 需求：发布流水线必须发布经过验收的同一产物

### 场景：标签不能绕过注册表发布门禁

- **给定** 现有 `release.sh` 只能准备版本提交和标签
- **当** 正式版本准备发布
- **则** 流水线必须先运行质量门、构建、压缩包审计和跨平台安装矩阵
- **且** 未通过任一必要检查时不得发布到 NPM
- **且** 版本、标签和包内版本必须一致

### 场景：公开注册表安装验证发布成功

- **给定** 候选压缩包已经通过全部门禁并发布
- **当** 发布后任务从公开注册表重新执行全局安装
- **则** 下载的包摘要或内容必须与候选产物一致
- **且** `ozw --version`、首次初始化、服务健康检查和 WebUI 静态入口必须通过
- **且** 失败时应阻止把该版本标记为稳定推荐版本并给出回滚步骤

## 需求：可选系统服务不得分叉运行边界

### 场景：系统服务复用同一程序和数据目录

- **给定** 用户选择安装 ozw 自身系统服务
- **当** 服务启动、显示状态或被卸载
- **则** 服务必须调用与前台 `ozw` 相同的已编译入口
- **且** 必须读取同一用户配置和数据库
- **且** 只能管理 ozw 自身进程，不得联动管理 Claude Code、Codex、Pi 或 Codex Server
- **且** 服务能力尚未实现时，前台 NPM 发行仍必须独立可用
