# 工作流阶段与会话处理时长渲染修复

## 场景

- oz flow 自动工作流已收敛为执行、优化、测试、归档四个业务阶段。
- 手动会话的“正文前过程”折叠摘要需要显示该轮已处理时长。

## 证据

- `workflowStageTableViewModel.ts` 仍将规划、审核、修正、QA 分成独立列，且不识别 `audit_N`、`targeted_repair_N`。
- `TurnNonBodyGroupBlock` 只保存过程消息，没有用户发起时间、正文完成时间或运行状态。
- 本机新版 oz 同时存在 `repair_N` 与 `audit_N`、`targeted_repair_N` 两代优化阶段键。

## 根因与置信度

- 工作流问题：展示层业务阶段映射未随 oz flow 状态合同更新。置信度：高。
- 时长问题：折叠块缺少轮次时间边界，渲染组件无法计算完成耗时或实时耗时。置信度：高。

## 修复方案

- 保留原始阶段键、会话和产物链接，仅在详情表展示层聚合为四列。
- 排除规划类预处理阶段，将新旧审核/修复键统一映射为“优化”，将 QA 显示为“测试”。
- 在过程折叠块记录用户发起时间、正文完成耗时和运行状态；完成态固定显示，运行态每秒刷新。

## 回归测试

- `tests/unit/workflow-detail-view-model.test.ts` 覆盖四列顺序、新旧优化键聚合、规划列排除和产物保留。
- `tests/specs/chat-rendering-parity.spec.tsx` 覆盖 83 秒完成耗时与实时处理时间锚点。

## 验证结果

- Vitest：13 个文件、70 项测试通过。
- 聊天渲染规格：23 项测试通过。
- Web、Node、测试 TypeScript 类型检查均通过。

## 剩余风险

- 非法或缺失消息时间戳时不会显示时长，以避免展示错误数字。
- 未识别的新阶段键仍按原有兜底逻辑处理；未来 oz flow 再变更阶段合同需同步展示映射。
