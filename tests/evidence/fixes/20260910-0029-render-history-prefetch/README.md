# 长会话连续上翻技术复查

## 根因

- `Confirmed`：Render 首屏只保留约一个视口附近的数据，用户进入顶部后才发起更早历史请求，磁盘读取和转换会直接阻塞滚动。
- `Confirmed`：旧逻辑只按整体高度差恢复位置；折叠卡片和异步内容改变高度时，当前阅读内容会发生偏移。
- `Confirmed`：有限历史请求仍会扫描并解析整个 JSONL，再截取尾部页；超长会话会放大顶部等待。

## 修复

- 保持最新正文优先的快速首屏；首屏绘制后静默预热约 6 个视口、最多 3 个原始页，不提前扩大 DOM。
- 用户进入顶部前 1 个视口时，从内存缓冲区一次补入约 3 个视口；补入后继续后台补足储备。
- 以当前可见消息行作为稳定锚点，历史插入和异步高度稳定后恢复同一行的屏内位置。
- Codex/Pi 有限历史页使用可复用行索引，从文件尾部按区间读取；完整读取和增量读取行为不变。

## 量化结果

- 1200ms 人工延迟接口：修复前顶部显示 `Loading older messages...`，500ms 内无新历史；修复后 500ms 内从缓冲区补入且锚点误差不超过 12px。
- 本地真实 `/projects/ozw/c2`：首屏 356ms；连续三次补入 320ms、201ms、201ms；三次锚点偏移均为 0px；控制台无错误。
- 39MB / 7694 行真实 Codex 记录：首次有限读取 90ms、解析 1792 行；复用索引后的相邻页 66ms，不再重新扫描索引。
