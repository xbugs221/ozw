# 长会话历史连续加载改造

## 用户现在会感受到什么

```text
打开长会话
   │
   ├─ 最新用户正文和智能体正文立即出现
   │
   └─ 空闲时在内存预热约 6 屏历史
                     │
用户继续上翻 ────────┘
   │
   ├─ 提前约 1 屏触发
   ├─ 直接补入约 3 屏
   └─ 当前阅读行保持原位
```

即使下一次历史接口需要 1.2 秒，用户到达顶部时也不再等待接口；页面先消费已经预热的数据，同时继续补充下一段储备。

## 修复前后

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 首次打开 | 最新正文快速出现 | 保持不变，真实长会话 356ms |
| 接近顶部 | 到顶后才读取，出现加载提示和停顿 | 提前预热，500ms 内直接补入 |
| 阅读位置 | 可能随新内容高度发生偏移 | 同一可见消息行稳定，实测 0px |
| 超长 JSONL | 有限页仍解析全文件 | 复用行索引并只解析需要的尾部区间 |

- [修复后：同一时刻已显示更早正文](after/delayed-top-load.png)

## 验收方式

打开任一很长的手动会话并切到 Render，等待最新正文出现后持续向上滚动。更早问答应在到顶前连续出现，视野中的当前消息不应跳位。
