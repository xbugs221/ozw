# 同一项目不再遗留大量 tmux 会话

## 这次给用户带来了什么

同一项目中打开的 Codex、Pi、Claude 和普通终端现在共用一个 tmux 会话，每个对话使用独立 window。离开终端后保留 5 分钟重连时间；期间仍有后台输出会自动顺延，真正静默后才关闭对应 window。最后一个 window 关闭后，tmux 会话也会自动消失。

## 如何验收

1. 在同一项目中分别打开两个不同的终端对话。
2. 查看 tmux 列表，应只有一个对应项目的会话，其中有两个可读的 window。
3. 离开其中一个终端，5 分钟内重新打开应恢复原现场。
4. 让它保持无输出超过 5 分钟，应只清理该 window，不影响同项目的其他对话。

实际验收已确认：两个 window 可同时存在于一个会话中，关闭其中一个后另一个仍正常存在。

## 修复前后对比

- 修复前：同项目的两个对话分别产生两个 tmux 会话，关闭时以整个会话为单位。
- 修复后：两个对话共用一个项目会话，分别位于 `codex_c1` 和 `pi_c2` window，回收互不影响。

## 已知限制

自动回收只管理 Ozw 打开的终端，不会清理用户自己创建的 tmux 会话。
