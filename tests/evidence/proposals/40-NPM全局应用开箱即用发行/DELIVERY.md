# 40-NPM全局应用开箱即用发行 交付报告

## 这次给用户带来了什么

- 用户安装预编译压缩包后可以直接启动工作台，不需要 Git、pnpm、TypeScript 或前端构建工具。
- 首次运行会自动创建私有配置和登录令牌，升级或卸载程序不会删除已有项目数据。

## 如何验收

### 验收前准备

- 准备受支持的 Node.js 版本以及维护者提供的 ozw 候选压缩包。

### 1. 全局安装后首次登录

- 用户价值：用户只需安装并运行一个命令，就能在本机浏览器打开工作台并安全登录。
- 步骤 1：把候选压缩包安装到隔离的全局目录，然后运行已安装的 ozw 命令。
  - 应看到：服务在本机回环地址启动，私有用户目录中生成登录配置，浏览器出现令牌登录页。
- 步骤 2：输入首次生成的访问令牌完成登录，然后刷新浏览器页面。
  - 应看到：工作台保持登录状态，重启后继续使用原有令牌和数据。
- 实测：真实候选压缩包已在隔离全局目录安装并启动，浏览器使用首次生成的访问令牌登录成功，刷新后仍保持内部会话。
- 直接证据：[首次安装与浏览器登录录像](first-run-browser-demo.webm)

### 2. 升级与卸载保留数据

- 用户价值：用户可以替换或卸载程序，而不丢失自己的配置、登录密钥和数据库内容。
- 步骤 1：写入一条数据库标记，重装候选包并重启服务，随后执行标准全局卸载。
  - 应看到：程序文件和全局命令被移除，但用户配置、内部密钥与数据库标记仍然存在。
- 实测：真实候选包完成重装、重启和标准全局卸载后，程序目录已移除，访问令牌、内部签名密钥与数据库业务标记均保持不变。
- 直接证据：[升级、卸载后的脱敏状态](installed-state-after-uninstall.json)

## 已知限制

- 公共 NPM 包尚未发布，正式发行前仍需确认包名归属并完成远端平台安装检查。
- Web 终端依赖本机可用的可选原生模块；该模块缺失时基础页面仍能启动，但终端功能不可用。
